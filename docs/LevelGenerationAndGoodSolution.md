# 关卡生成器和好解检查原理

## 入口

编辑器里的“生成地图”按钮会调用 `POST /api/levels/generate`。后端要求开发者 Bearer Token，通过后才由 `server/services/generator.py` 读取 `config/settings/generator.json`，按难度和网格类型选一组生成参数，再以 `--dry-run --json --no-rebuild` 调用 `scripts/generate-alpha-levels.mjs`。

编辑器里的“检查好解”按钮会调用 `POST /api/levels/check-good`。后端同样要求开发者 Token，随后把当前编辑器地图和作者答案交给 `server/services/good_checker.py` 做逐对局部最短路检查。

命令行调试生成器时建议使用：

```bash
node scripts/generate-alpha-levels.mjs --dry-run --json --no-rebuild --type square --difficulty 3 --pairs 5
```

`--dry-run` 表示只输出结果，不写入 `data/levels` 和 `data/answers`；`--json` 让输出可被后端解析；`--no-rebuild` 避免重建索引。

## 生成器流程

生成器不是随机摆点后直接保存，而是“构造答案，再反推谜面”：

1. 读取目标网格类型、尺寸、点对数、难度、随机种子和尝试次数。
2. 为指定网格枚举所有节点和边。方形网格只有水平/垂直边，直角三角形额外加入交错对角线，正三角形使用轴坐标邻接边。
3. 生成若干条互不冲突的答案路径。每条路径连接一个点对的两个端点，路径之间不能共享节点或边。
4. 将路径端点写入 `pairs`，答案路径写入 `answers`，所有新生成关卡都保持 `removedEdges=[]`。
5. 对候选关卡做结构校验。方格生成使用“好解”检查；三角格生成暂时搁置，不作为当前质量目标。通过后输出 `{ map, answers }`；不通过就换种子或换候选继续尝试。

难度主要由 profile 控制：地图尺寸、点对数量、候选筛选数量和回环处理次数都会影响分支数量。方格不再依赖删边，当前目标是生成“每条作者路径都没有局部更短替代路”的好图。

## 难度配置

方格的 `width/height` 表示格子数，实际落点数是 `(width + 1) * (height + 1)`。难度为 `x` 时，宽度取 `3x-2` 到 `3x+2`，高度取 `2x` 到 `2x+2`，点对数量取 `min(width,height)+1`。编辑器和后端的方格宽高上限同步放宽到 17，以覆盖难度 5 的 `17x12 / 13 对`。

| 难度 | 方格配置 |
| --- | --- |
| 1 | `1x2 / 2 对`，`2x3 / 3 对`，`3x4 / 4 对`，`4x4 / 5 对`，`5x4 / 5 对` |
| 2 | `4x4 / 5 对`，`5x5 / 6 对`，`6x6 / 7 对`，`7x6 / 7 对`，`8x6 / 7 对` |
| 3 | `7x6 / 7 对`，`8x7 / 8 对`，`9x8 / 9 对`，`10x8 / 9 对`，`11x8 / 9 对` |
| 4 | `10x8 / 9 对`，`11x9 / 10 对`，`12x10 / 11 对`，`13x10 / 11 对`，`14x10 / 11 对` |
| 5 | `13x10 / 11 对`，`14x11 / 12 对`，`15x12 / 13 对`，`16x12 / 13 对`，`17x12 / 13 对` |

方格现在采用标准 Numberlink 口径：不删除边，完整方格图上只给端点。生成器先构造一张铺满全图的答案覆盖，再检查每一对点是否有局部更短路；通过后再按转折、重叠、长度均衡和边界占用评分挑候选。

直角三角和等边三角生成暂时保留现状，不作为当前优化目标。它们后续需要单独重写路径构造和验收逻辑。

编辑器生成配置只保留两层：

1. `editorGenerator.defaults`
2. `editorGenerator.profiles[difficulty][gridType][i]`

因此 `profiles` 里只需要写尺寸、点对数量和少量例外值。公共的 `attempts`、`qualityCandidates`、`loopPasses`、`timeout`、`radius` 都放在默认层，避免每个候选重复维护。完全相同的候选可用 `repeat` 表示重复权重，后端展开后会删除这个内部字段，不会传给生成器。`solveMs` 不再属于地图生成配置；它只用于编辑器里的“检查好解”接口。

## 方格好解算法

把地图抽象为无向图 `G=(V,E)`：节点 `V` 是可落点，边 `E` 是当前网格类型允许连接的线段。一个完整答案是一组点不相交的简单路径 `P1..Pk`，每条路径连接一个点对 `(si, ti)`，并且满足：

- `Pi` 的首尾分别是同一个点对的两个端点；
- 不同路径不共享节点；
- `P1..Pk` 的节点并集刚好等于 `V`，即所有点对连通后自然铺满整张地图。

方格生成方式是“先构造完整答案，再反推谜面，再做局部最短路验收”：

1. 使用参考 Numberlink 生成器得到一张无自接触的完整路径覆盖。
2. 将参考覆盖追踪为 `k` 条答案段，每段首尾作为一个点对。
3. 保留完整网格边，要求 `removedEdges=[]`。
4. 对每一对点单独检查“断开这一对”后的局部替代路。
5. 具体做法：其他点对的答案路径视为占用；只释放当前点对原答案路径上的节点。在这些可用节点诱导出的完整方格边里，用 BFS 找当前两个端点的最短路。
6. 如果存在比作者答案段更短的路径，这一对不是好解，整张候选图丢弃。
7. 每一对都没有更短替代路时，候选图通过；随后按转折更多、长直段更少、路径包围盒更互相重叠、长度更均衡、端点不过度贴边打分。
8. 最终输出必须满足 `removedEdges=[]`，生成器保存前会做硬校验。

这个方法的关键是把“铺满”变成构造性质，把“好解”变成局部最短路性质，直接排除玩家最容易看到的坏情况：某条线明明可以在不动其他线的前提下走得更短。

## 耦合度设计

高耦合地图不靠删边，而是让局部选择影响多个路径的覆盖关系。生成器评分优先选择以下结构：

1. 不同答案路径的包围盒大量重叠，局部改线会挤占其他路径。
2. 端点不要集中贴边，避免每条路径只沿外圈绕行。
3. 转折密度高、长直段少，减少层层遍历的机械感。
4. 路径长度较均衡，不让一个超长路径承担全部覆盖约束。
5. 每条路径在自身释放区域内没有更短路，避免明显绕远。

可量化的耦合指标包括：好解通过率、候选评分、路径包围盒重叠率、路径长度方差、方向变化率、边界使用率，以及逐对最短路检查结果。

## 参考生成器口径

`files/numberlink-master` 里的参考实现是高质量方格答案来源。项目里方格生成只借用 `gen/gen.py` 生成“无环、端点不相邻、路径不自接触”的管线，再把其彩色管道追踪成答案段；最终由本项目好解检查器验收，而不是原样信任参考生成器。

参考实现有两条生成思路：

- `gen/gen.py` 在双倍尺寸网格上画左右边界路径，再向中间加入随机 loop，使用 `has_loops`、`has_pair`、`has_tripple` 过滤无效或质量差的管道图。
- 旧 Go 版 `gen.go` 先用 2x1 domino 铺满棋盘，随机翻转相邻 domino，再把相邻区域合并成 flows，避免自接触后输出端点谜面。

这些思路都体现了同一个原则：先得到一张完整的路径覆盖，再从路径覆盖中抽取端点谜面。项目自己的三角网格生成器采用更通用的图论版本，便于扩展到任意网格。

## 不同格子类型

统一算法只依赖两个图接口：`getGridNodes(level)` 枚举节点，`getAllGridEdges(level)` 枚举合法边。只要新网格能提供这两个接口，就可以复用“答案覆盖、切段、局部最短路验收”的框架。

### square

方格图的节点是 `(x,y)`，边是水平/垂直相邻点。当前方格生成优先使用 `files/numberlink-master/gen/gen.py` 作为答案来源，因为它能生成更自然的无自接触管道；随后只抽取端点，保持完整网格，不删除边。生成器用逐对 BFS 检查是否存在更短替代路，通过后按质量评分挑选候选。

### right-triangle

直角三角网格在矩形点阵上增加交错方向的对角边。答案路径优先使用随机化 Warnsdorff/回溯生成；回溯失败时只允许把矩形蛇形当作初始覆盖种子，再用 backbite 重连和局部翻转打散。原始蛇形不会直接通过验收。质量门主要看方向变化率和最长轴向连续段，避免层层遍历或横平竖直填图。三角格当前只保留结构生成，后续需要补齐对应晶格的好解检查。

### equilateral-triangle

等边三角网格使用轴坐标 `(q,r)`，节点满足 `max(abs(q), abs(r), abs(q + r)) <= radius`，合法边方向是三组 60 度方向。它不是矩形行列结构，初始哈密顿路径使用带启发式的回溯：每步优先走后续可走邻居更少的节点，同时加入随机扰动并惩罚同方向、同环层长跑。三角格当前只保留结构生成，后续需要补齐对应晶格的好解检查。

## 设计边界

- 好解检查依赖作者答案：`answers` 必须能还原每个点对的一条简单路径。
- 方格好解按“节点覆盖 + 局部无更短路”定义：作者答案必须覆盖所有可通行节点，且逐对释放自身路径后没有更短连接。
- `answers` 用于编辑器回显和审核，不写入玩家加载的关卡本体。
- 新建关卡保存前还会计算结构哈希，拒绝和已有正式/测试关卡重复的地图结构。
